# Runbooks

Procedures that are followed under time pressure, so they are written to be
executed rather than read.

| Runbook | When |
| ------- | ---- |
| [`field-test.md`](field-test.md) | Before a pilot, and after any change to the location cadence. **Built, not run** — it needs a car, a driver and two phones. |
| [`pilot-readiness.md`](pilot-readiness.md) | Before any test with people who are not on the team. What has to become real, and what blocks what. |
| [`release-ios.md`](release-ios.md) | Putting either app on an iPhone, into TestFlight, or into the App Store. |
| [`release-android.md`](release-android.md) | Putting either app on a handset, onto a Play test track, or into production. |
| `restore-drill.md` | Quarterly, and after any backup configuration change (Stage 4) |
| `incident-response.md` | A suspected data exposure (Stage 4) |
| `production-deploy.md` | Every production release (Stage 4) |

A completed restore drill is filed here with its **measured** wall-clock time
and anything that went wrong. A drill that goes perfectly and is not written
down has taught nobody anything.
